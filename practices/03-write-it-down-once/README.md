# 03 — Write It Down Once, Don't Correct Twice

**The idea:** every correction should become a permanent rule somewhere
durable (a memory file, a skill, a CLAUDE.md), not a one-off fix repeated
in conversation. Correcting something in the moment fixes that one
instance; writing the fix down fixes every future instance. The trigger
line worth remembering: *the moment you catch yourself giving the same
correction twice, write it down once instead.*

## What's here

- `LESSONS.md` — a starter memory file, seeded with one real example rule
  pulled from a bug in `practices/01-verification/calc.py`.

## Exercise

1. Think of something you've corrected more than once recently — in code,
   in a workflow, anywhere. It doesn't have to be from this repo.
2. Add a new entry to `LESSONS.md` in the same format: **Rule**, **Why**,
   **How to apply**. Writing the "why" is what makes the rule usable later
   — without it, future-you (or a future agent) can't tell whether an edge
   case is covered or not.
3. Next time you'd make the same correction, check `LESSONS.md` first
   instead of re-deriving it.

The value of this practice doesn't show up on the first pass — it shows up
the second time the same mistake almost happens again, and doesn't.
